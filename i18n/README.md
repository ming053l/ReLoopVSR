# Translated pages

The English page `../index.html` is the only page edited by hand. The pages `../zh-Hans/`, `../zh-Hant/`, `../ja/` and `../ko/`
are generated from it by `build_i18n.py`, and they share `../assets` and `../media` (nothing is copied).

## Files

- `build_i18n.py` builds the four translated pages and refreshes the language switcher and the hreflang / Open Graph block of the English page.
- `<lang>.json` holds one translation per language:
  - `"html"` maps each English unit of the page to its translation. The key is the English text exactly as it appears in `index.html`, including its inline markup (`<b>`, `<i>`, `<span …>`, `<small>`), with whitespace collapsed. The value must keep the same tags and attributes and must not contain an ASCII `"`.
  - `"js"` holds the strings that `assets/app.js` and `assets/schematic.js` create at run time (keys `sch.*` belong to the schematic). Placeholders such as `{n}` and `{res}` must stay. The page receives this dictionary as `window.DV_I18N`, and any key it lacks falls back to English.
- `en.json` is the catalogue of all English source strings. It is generated by `--extract`, and the translators work from it.

## After editing the English page

```
cd deliverables/project_page
python3 i18n/build_i18n.py --extract    # refresh en.json, rebuild, list missing / stale strings per language
```

For each string that a language reports as missing, add a key in that language's `<lang>.json` with the new English text and its translation. Delete any key that the build reports as stale (unused). Then run `python3 i18n/build_i18n.py --strict`, which exits with status 1 while a string is still missing. A missing string is not an error in the page itself, since it simply appears in English.

- A string that must stay English everywhere, such as a name or a number, can be mapped to itself.
- Wrap text in an element with `translate="no"` to remove it from the catalogue, as the authors, the affiliations and the BibTeX already are.
- Units without a lowercase word, such as `720p`, `PSNR ↑` or `K=4`, are never translated.

A new user-visible string in `app.js` or `schematic.js` goes through `T('key','English text',{vars})`, and `--extract` then picks it up.

Finally, copy the changed files, including the four language folders, into the deploy repo and the mirror.
